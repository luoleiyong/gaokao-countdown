## 3. 制作流程

### 3.1 生成视频

用 AI 视频工具生成 720×720、24fps、约 5 秒的角色动画。要求：

- Q 版蓝发大肥鱼，坐在同款课桌前，与现有立绘一致
- 纯色绿幕背景，不要地面阴影
- 固定机位、全身入镜、首尾帧接近写作业姿势
- 头顶气泡类动作（问号、省略号、食物）要完整出现在画面内

### 3.2 抽帧

用 ffmpeg 按 24fps 抽出 121 帧：

```bash
ffmpeg -i input.mp4 -frames:v 121 -start_number 1 frames/f%03d.png
```

视频时长约 5.06 秒，与 121 帧 × 24fps 对齐。

### 3.3 绿幕抠像

视频背景不是纯亮绿，而是带灰度的浅绿（约 RGB 125,150,121），因此没有用简单的 `#00FF00` 差值，而是按「绿色相对红/蓝的占比」计算 alpha：

```python
d = g - max(r, b)
ratio = d / max(1, r + g + b)
alpha = clip((0.030 - ratio) / 0.020 * 255, 0, 255)
```

随后做三步清理：

1. `MedianFilter(3)` 去噪
2. `alpha < 120` 直接置 0
3. `MinFilter(5) → MaxFilter(5) → MinFilter(3)` 形态学开闭运算，去掉边缘碎点

颜色侧再做去绿：`g = min(g, max(r, b))`，避免半透明边缘残留绿色。

### 3.4 裁切与缩放

720×720 原图统一裁切 `x 8–716, y 24–712`，再缩放到 206×200。裁切框能同时容纳角色、课桌和头顶气泡，并让所有动作与写作业循环保持同一构图。

缩放采用预乘 alpha，避免透明边缘发黑：

```python
pre[:, :, :3] *= pre[:, :, 3:4] / 255
img = img.resize((206, 200), Image.LANCZOS)
```

最后再反预乘并保存为无损 WebP：

```python
img.save(path, 'WEBP', lossless=True, quality=100, method=4)
```

### 3.5 播放

- `app.js` 中 `HW_FRAME_COUNT = 169`、`HW_FPS = 24`、`HW_ACTION_FRAMES = 121`
- 写作业循环和动作共用 `#petFishHwFrames` 这一块 canvas
- `fishMaybeHomeworkAction(text)` 在气泡台词命中时加载对应动作的 121 帧
- `fishStartHwFrames()` 用 `requestAnimationFrame` 按 24fps 绘制；动作播完自动回到写作业循环
- 加载失败时自动回退到 `feiyu-homework.webm`

## 4. 研究过程

### 4.1 参考项目：待机动画不是 CSS

最初待机动画只是对静态立绘做 CSS 缩放和位移，看起来仍然是一张图。研究 `QCYTSN/dsh-dafeiyu` 与 `PC2005-cloud/dsh-pet` 后发现，参考项目是用 **完整的透明动画帧**（呼吸、伸懒腰、打哈欠、吃 Token）循环播放，而不是给静态图加动效。

据此改成真实动画片段：`feiyu-idle.webm` 常驻循环，伸懒腰/打哈欠/吃 Token 作为独立片段随机插入，播完回到呼吸。上课奔跑、课间待机、放学写作业分别由 `renderFish()` 根据 `coursePlan()` 的状态切换。

### 4.2 绿边问题：VP9 alpha 的色度压缩

写作业动画最初用 VP9 带 alpha 的 WebM。实际运行时，角色边缘在透明过渡区会周期性闪出绿色颗粒。原因是 VP9 的 alpha 与色度分平面压缩，半透明边缘的绿色无法完全去掉，缩放后更明显。

尝试过提高码率、改像素格式、加 CSS 描边，都无法根除。最终参考项目作者的做法：**放弃视频 alpha，改成逐帧无损 WebP + Canvas 播放**。WebP 每帧自带干净的 alpha，不再经过视频色度压缩，绿边彻底消失。

- 写作业循环：169 帧
- 每个互动动作：121 帧
- 播放：`requestAnimationFrame` + 24fps 时间轴，先清除画布再 `drawImage`

### 4.3 抠像参数迭代

早期直接用「绿色分量减红蓝」做阈值，浅绿背景会残留大片半透明噪点；提高阈值又会把角色的蓝色头发边缘吃掉。最终改为按比例判断：

- `ratio = (g - max(r,b)) / (r+g+b)` 对亮度不敏感，深浅绿背景都能处理
- 阈值区间 `0.030 → 0.050`，配合中值滤波和形态学清理
- 去绿步骤保证半透明边缘不会偏绿

处理后逐帧统计「alpha > 20 且绿色明显高于红蓝」的像素数，当前 11 组动作的最大值均为 0。

### 4.4 动作与台词的绑定

需求是「说到对应的话才做动作」，而不是随机播放。实现分三层：

1. `HOMEWORK_ACTIONS` 维护 key → 台词列表的映射（当前 11 组、26 条台词）
2. `fishSay(text)` 每次设置气泡后调用 `fishMaybeHomeworkAction(text)`，精确匹配台词
3. 命中后异步加载该动作的 121 帧，加载完成写入 `fishState.hwAction`，由 canvas 时间轴播放

后来发现一个实际问题：写作业气泡每 150 秒才说一句，而约 120 条台词里只有十几条绑定动作，平均约 20 分钟才看得到一次动作。为此增加定时动作：

- 进入写作业约 35–50 秒后出现第一个
- 之后每 95–140 秒一个
- 动作 key 放入洗牌袋，11 个动作一轮内不重复
- 定时触发时同步说一句该动作绑定的台词，保证「台词 + 动作」同时出现

设置中的「桌宠互动频率」（安静 / 慢 / 快 / 极快）会整体缩放台词、待机小动作和写作业动作的间隔（3× / 1× / 0.55× / 0.3×，最低 8 秒）。

### 4.5 学科台词

写作业台词由两部分合并：

- `FISH_CHEER_LINES`：通用鼓励与学习习惯（152 条）
- `FISH_SUBJECT_LINES`：十门学科各 6 条知识提醒

只合并设置中勾选的科目；`homeworkLines()` 按选科组合缓存，换选科后自动重建。学科台词不绑定动作，只作为普通气泡；通用台词中的 26 条与动作一一对应。

### 4.6 验证方式

- 静态检查：11 个动作 key、26 条绑定台词无重复/冲突/漏配；10 个科目各 6 条；学科台词与动作台词无交叉
- 逐条触发：在真实渲染页面中依次用每条绑定台词触发，检查 `hwAction.key` 与 canvas 非透明像素数
- 轮换检查：连续抽取 11 次，确认 11 个动作各出现一次
- 画面检查：首尾帧、透明边缘、气泡完整性

## 5. 新增一个动作的步骤

1. 生成 720×720、24fps、约 5 秒、绿幕背景的视频
2. 抽 121 帧到临时目录
3. 用 `docs/character-actions.md` 第 3.3–3.4 节的参数抠像、裁切、缩放
4. 输出到 `renderer/assets/hwact/<key>/f001.webp … f121.webp`
5. 在 `renderer/app.js` 的 `HOMEWORK_ACTIONS` 中加入 `{ key, lines }`
6. 把 `lines` 同步加入 `renderer/fish.js` 的 `FISH_CHEER_LINES`
7. 运行验证：台词触发、帧数 121、尺寸 206×200、绿边像素为 0

## 7. 已知限制

- 台词触发为精确文本匹配，气泡文案必须与 `HOMEWORK_ACTIONS` 中的字符串完全一致
- 所有动作固定 121 帧，新增素材需要按 5 秒左右生成，过长或过短需重采样
- 逐帧素材体积较大：11 组动作约 50 MB，写作业循环约 5 MB
- 动作帧与写作业循环共用 206×200 画布，新素材需保持相同构图，否则角色大小会跳变
